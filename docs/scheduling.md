# 定时运行

## 只能挂一个

`src/live/` 下有两个入口, **调仓节奏只能有一个**, 不要同时挂进 crontab:

| 入口 | 节奏 | 适用 |
|---|---|---|
| `run_weekly.sh` | 自然周固定时间 | 默认。好记、好对账 |
| `run_decision_day.sh` | 自锚定日起每 5 个交易日 | 想严格贴合回测调仓网格时 |

两者都用 `flock` 取排他锁, 撞车时后来者直接退出而非并发跑——但那是防手滑,
不是让你同时挂两个的理由: 一周调两次仓, 换手翻倍, 成本假设就不成立了。

## 当前配置

```
0 20 * * 0  src/live/run_weekly.sh >> output/live/weekly_cron.log 2>&1
```

周日 20:00 运行, 信号取上周五收盘数据。执行按路径 B:

- 周一 11:30 前 —— 卖出腿
- 周一 13:30–14:30 —— 买入腿

**不要开盘集中下单。** val 段实测开盘买入比午后贵 13–17bp/笔。

## 自然周 vs 5 个交易日

回测的调仓网格是"每 5 个**交易日**", 自然周在节假日周会变成 4 天或 6 天。
这是一个已知的、无法两全的偏离:

- 钉自然周 → 节假日周的持有期长度浮动
- 钉 5 个交易日 → 出表日在周一到周五之间漂移, 不适合固定时间收报告

选了自然周, 因为报告要定时送达。相位稳健性检验(`src/test/phase_robustness.py`)
量化了调仓相位对业绩的影响——若结论是"敏感", 说明回测曲线有相当部分来自
"恰好在那些日子调仓", 那才需要回头重新考虑这个取舍。

## 脚本在哪些情况下拒绝出信号

宁可不出, 也不在坏数据上出:

1. 源数据超过 5 天未更新
2. `pipeline.py --check` 缓存一致性未通过(维度不一致 / 缓存比源数据旧)
3. 流水线任一阶段报错

前两种会发一封失败通知邮件(若已配 SMTP), 并以非零码退出。

## 邮件

凭证放项目根 `.env`(已 gitignore), 从不写进代码或仓库:

```
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的邮箱
SMTP_PASS=授权码          # 不是登录密码
MAIL_TO=收件人
```

QQ 邮箱的授权码在 设置 → 账号 → 开启「POP3/SMTP服务」后生成。
服务器上的 postfix 是停的, `mail`/`sendmail` 发不出去, 所以走 Python 直连 SMTP。

连通性测试:

```bash
python src/live/send_report.py --test
```

未配置 SMTP 时信号照常落地到 `output/live/`, 只是不发信——脚本会明确记一行日志,
不会静默失败。
