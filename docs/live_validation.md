## 已修正的缺陷

**1. fi_grid 列数与列序**
流水线原先只建 2 列(roe / stat_date), 而研究链按 6 列解包(`STAT=FIG[:,4]`)。
更要命的是 `generate_portfolio` 中 stat_date 读的是第 1 列——那是 SUE 不是
stat_date, 会让 dROE 结构分算错**且不报错**。已按研究期口径补齐 6 列并修正列号。

**2. 研究链兼容缓存不随流水线重建**
`nets_v8` / `nets_v41_flow` / `nets_v47_te` / `nets_v17` 原为一次性拷贝。
codes 维度变化后(新股上市 5469 → 5471)不同步重建, 研究链会按错位索引出结果。
已纳入 `pipeline.py --stage research` 并加维度断言。

**3. 对拍脚本自身的缺陷(第一版结论作废)**
第一版对拍在 5 个日期上得到 7/6/124/4/10 的交集(随机重叠约 15.8), 看似"低于随机"
的严重判负。实际原因: 回测的锚变量只在信号网格日期上计算, 其余日期为 NaN。
5 个日期只有 1 个在网格上。**在非网格日期上比较等于拿现算值比空值。**
已改为只取网格日期。同一缺陷也让相位检验崩溃(换相位=换日期→锚变量全 NaN),
已加逐相位补算。

**4. ROE 锚方向写反(组件差分定位)**

逐块比较给出的结果非常干净:

| 中间量 | 相关 | 最大差 |
|---|---|---|
| vol20 / mom20 / gap_price / zspread / gap_dual / gap_te | +1.000000 | 0 |
| sweep_sell / osize_sell / behavior / structure / droe | +1.000000 | 0 |
| 域大小 / lim250 / tradable | 完全相等 | — |
| **gap_roe** | **−1.000000** | 3.5e+02 |

除 ROE 锚外每一块都逐位精确, `base_score`(0.79)与 `COMB`(0.85)的偏差
**全部由这一个符号反转传导**。

原因是方向语义在两类锚之间相反:

- 价格锚 `邻居 − 自身` —— 邻居涨了自己没跟上 = 待追赶, 正
- 基本面锚 `自身 − 邻居` —— 自己基本面比邻居好 = 质量, 正

重写时套用了价格锚的方向。已修正并补上回测中 `~isnan(m[idx])` 的自身非空条件。

> 这一条是做对拍的全部意义所在: 符号反转不报错、不产生 NaN、结果看起来完全正常
> (排名合理、行业分散、换手正常), 只是选出来的不是那个被验证过的组合。

## 未决

**B. 缓存重建后历史结果不完全复现**
项目记录 dev 17.0% / val 18.6%; 全部缓存按当前源数据重建后, 相位0 得到
dev 16.2% / val 17.9%。dev 与 val 是**固定窗口**, 数字本不该变。
差异约 0.8pp, 说明报告中的数字与某一版数据快照绑定(源数据修订、新股纳入
相关性全域等)。这不是错误, 但意味着"19.4%"不是一个可逐位复现的常数。

**C. dROE 覆盖率的季节性空洞**
覆盖率均值 0.49, 但 **21.3% 的交易日不足 8%**。此时 `fin.sum()>200` 不成立,
dROE 项静默退回全 1, 结构块只剩"股价≥2元"一项生效。公式与研究代码逐字相同,
是策略固有性质(财报按季集中发布, 60 日窗口不跨发布期就没有新报告), 非本次引入。
